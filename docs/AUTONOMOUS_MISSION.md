# AUTONOMOUS MISSION — Overall teaching scene

## Open and controls

Open `index.html` → `pages/overall.html#system`. One SIM click runs station preparation → route post → real browser receipt pending application → boat validation/storage → separate START post/receipt → readiness → navigation and reports back. A fresh boat has no accepted route or navigation target; the nine points shown beforehand are explicitly the station's supplied example. GPS/compass/safety inputs are synthetic, explicit faults remain unchanged, and HOME is not a START prerequisite. PAUSE freezes mission time and pose even when a native message arrives. NEXT STEP begins/continues this same story, advances one captured50ms tick and returns paused; a tick may still be waiting for the next setup stage. RESET clears mission and retires both incoming and outgoing generations. Five focus tabs change explanation only. Phone map pans within its own frame.

The visible setup holds use1400ms of the same model clock per explanation stage (700ms at default2×), not a second timer or a claimed firmware/radio latency. Actual native receipt is shown honestly as received/waiting while controlled application is paused or held. Separate commands use a browser-only immutable MessageChannel envelope with x/y points, generation, route and message IDs; this is NOT a serializer or execution test of real ESP-NOW packets. Local boat acceptance is not a delivered shore ACK. The bounded teaching subset supports one batch index0 with1..12 finite points; it rejects unsupported batches/counts/coordinates. A short batch seals immediately; START seals a stored12-point batch. A normal START may remain pending for route/GPS/compass; unsafe START is consumed/refused, not silently retried. There is no route editor, multi-batch upload, real shore planner or radio retry emulation.

`ROUTE` reveals the schematic area, supplied nine-point route, numbered waypoints, then current path. Coordinates remain HOME `(335,455)`; WP1 `(440,170)`, WP2 `(440,280)`, WP3 `(440,390)`, WP4 `(665,390)`, WP5 `(665,280)`, WP6 `(665,170)`, WP7 `(890,170)`, WP8 `(890,280)`, WP9 `(890,390)`. This is a supplied teaching route, not an attributed onboard/shore generation algorithm.

NAVIGATION shows the current GRID line-of-sight (LOS) bearing: a 6 m lookahead on the accepted route segment, in schematic-local metres converted at 0.15 m/unit. Waypoints advance at a 3 m radius with along-track progress or a 0.5 m pass margin plus cross-track guard; the bearing error wraps to [-180°,180°). The small boat glyph remains anchored at the canonical pose and rotates with heading; no heading line/arrow is drawn from it. CONTROL shows the current GRID continuous measured-rate steering/surge controller, joint motor allocation and DriveController shaping, versus the unchanged illustrative SPIRAL/RTH error-derivative PID. Requested PWM and final applied PWM are shown separately; only applied commands enter the illustrative plant. Faults/holds/park stop drive. Plant response is synthetic and is not calibrated thrust/GPS behavior. ADD DISTURBANCE affects this plant, not a decorative offset. WATER arms the red region in the actual synthetic ADS stream.
